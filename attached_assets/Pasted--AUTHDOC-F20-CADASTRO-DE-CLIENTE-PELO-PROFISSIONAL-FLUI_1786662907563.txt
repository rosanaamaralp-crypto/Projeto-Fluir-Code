# AUTHDOC F20 — CADASTRO DE CLIENTE PELO PROFISSIONAL

## FLUIR DA VIDA OFICIAL

### OBJETIVO

Implementar a possibilidade de o PROFESSIONAL cadastrar um novo CLIENT diretamente pelo sistema.

Essa necessidade foi identificada após o uso real do MVP em produção.

O objetivo é permitir que o profissional consiga cadastrar um cliente durante sua rotina de atendimento e, em seguida, realizar o agendamento para esse cliente sem depender do ADMIN.

A funcionalidade deve ser simples, segura e reutilizar ao máximo a estrutura existente.

---

# 1. REGRA DE NEGÓCIO

Alterar a regra atual:

### Atualmente

POST `/api/clients` aceita criação de cliente somente pelo ADMIN.

### Nova regra

ADMIN e PROFESSIONAL podem criar CLIENTES.

CLIENT não pode criar outro CLIENT.

O PROFESSIONAL poderá criar um cliente para viabilizar seu próprio atendimento/agendamento.

---

# 2. SEGURANÇA E OWNERSHIP

Esta alteração NÃO deve transformar PROFESSIONAL em administrador.

O PROFESSIONAL continua sem acesso a:

- criação/edição de profissionais;
- serviços;
- recursos/macas;
- configurações administrativas;
- permissões;
- auditoria administrativa;
- outros módulos exclusivos do ADMIN.

Ao criar um CLIENT, registrar corretamente quem realizou a criação, utilizando o mecanismo de auditoria existente, caso já aplicável.

O PROFESSIONAL não deve ganhar acesso irrestrito à lista global de clientes.

Após a criação, o cliente deve ficar disponível para o profissional que o cadastrou para fins de atendimento/agendamento.

Reutilizar o conceito de ownership/relacionamento profissional → cliente já utilizado pela F19.

NÃO inventar uma nova regra de relacionamento se a estrutura existente puder ser reutilizada.

---

# 3. CADASTRO DO CLIENTE

Reutilizar a tela, validações e componentes existentes de cadastro de cliente do ADMIN sempre que possível.

Campos mínimos existentes:

- nome;
- data de nascimento;
- telefone;
- e-mail;
- senha, se atualmente obrigatória no cadastro interno;
- endereço, quando aplicável.

Antes de alterar o modelo de cadastro, verificar como o cadastro de cliente atualmente funciona no ADMIN.

Não duplicar lógica desnecessariamente.

---

# 4. FLUXO DO PROFESSIONAL

O PROFESSIONAL deverá ter uma forma clara de:

**Clientes → Novo Cliente**

ou equivalente dentro da área PROFESSIONAL.

Após salvar:

1. cliente é criado;
2. cliente fica associado ao profissional conforme a regra de relacionamento existente;
3. profissional recebe confirmação de sucesso;
4. profissional pode visualizar o cliente;
5. profissional pode iniciar um novo agendamento para esse cliente.

Se for possível reutilizar o fluxo já existente de `/professional/book`, preferir essa abordagem.

---

# 5. INTEGRAÇÃO COM F19

A funcionalidade deve funcionar naturalmente com a F19.

Fluxo esperado:

**Professional → Novo Cliente → Salvar → Cliente criado → Novo Agendamento → Cliente selecionado → Serviço vinculado → Modalidade → Data → Horário → Confirmação**

Não alterar as regras já implementadas na F19.

Continuam obrigatórias:

- profissional agenda somente para si próprio;
- `professionalId` não pode ser usado para spoofing;
- serviço precisa estar vinculado ao profissional;
- regras de disponibilidade continuam válidas;
- bloqueios continuam válidos;
- regras de maca continuam válidas;
- regras de Home Care/endereço continuam válidas.
