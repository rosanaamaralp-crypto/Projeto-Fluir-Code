B. Objetivo da Fase
Implementar o módulo de notificações internas do sistema Fluir da Vida, composto de:

Geração de notificações — NotificationService invocado pelos services de Appointments nos eventos de criação, alteração, cancelamento e conclusão, criando registros na tabela notifications já existente.
Leitura de notificações — GET /api/notifications retorna as notificações do usuário autenticado com suporte a filtro opcional por não lidas e paginação.
Marcação como lida — POST /api/notifications/:id/read marca uma notificação como lida, protegida contra IDOR.
Nenhuma integração externa (e-mail, WhatsApp, SMS). Somente notificações internas, conforme Doc 18 PROMPT 16: "Não implementar integrações externas ainda."

F. Fluxo Técnico de Implementação
F8.1 — NotificationService (src/services/notifications.service.ts)
Método único: NotificationService.create(db, entry) — insere uma notificação na tabela notifications. Não gera audit log.
Tipos de notificação (constantes): APPOINTMENT_CONFIRMED, APPOINTMENT_ALTERED, APPOINTMENT_CANCELLED, APPOINTMENT_COMPLETED, NEW_APPOINTMENT_RECEIVED.
Mensagens geradas dinamicamente com dados do agendamento.
Chamado de AppointmentsService com a mesma instância de db após o commit principal.
F8.2 — Modificação de AppointmentsService
create(): chamar NotificationService.create() para CLIENT e PROFESSIONAL após commit.
alter(): chamar para CLIENT e PROFESSIONAL.
cancel(): chamar para CLIENT e PROFESSIONAL.
updateStatus() ao atingir COMPLETED: chamar para CLIENT (opcional D1).
Falha na notificação não deve reverter a operação principal (try/catch isolado — notificação é best-effort).
F8.3 — Validator (src/validators/notifications.validator.ts)
ListNotificationsQuerySchema — query params: unread (boolean coercive), page, limit.
NotificationParamsSchema — params: id (UUID).
F8.4 — Repository (src/repositories/notifications.repository.ts)
create(db, entry) — insere notificação.
findManyByUserId(db, userId, filters) — SELECT + COUNT paginado filtrando por user_id (e opcionalmente read_at IS NULL). Ordenação: created_at DESC.
findById(db, id) — busca uma notificação por ID (para IDOR check).
markAsRead(db, id) — UPDATE read_at = NOW() WHERE id = id. Idempotente (se já lida, não recria).
F8.5 — Controller (src/controllers/notifications.controller.ts)
list() — GET /notifications: lê userId da sessão, chama repository, retorna paginado.
markAsRead() — POST /notifications/:id/read: valida UUID, busca notificação, verifica ownership, atualiza read_at.
F8.6 — Routes (src/routes/notifications.ts)
GET /notifications → requireAuth + validateQuery + controller.list
POST /notifications/:id/read → requireAuth + validateParams + controller.markAsRead
