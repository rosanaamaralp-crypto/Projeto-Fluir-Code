Especialmente:

### Criar CLIENT

```text

```

### Criar PROFESSIONAL

Deve ser atomicamente:

```text

+
create professional
```

### Audit logs

Quando uma operação exige audit log, confirme:

```text
operação principal
+

```

estão na mesma transaction quando a atomicidade é necessária.

Procure casos em que:

```text
INSERT/UPDATE
COMMIT
INSERT audit_logs
```

possa acontecer, pois isso criaria inconsistência.

# 13. AUDITORIA DE SLOTS

Inspecione:

```text
services/slots.service.ts
controllers/slots.controller.ts
validators/slots.validator.ts
routes/slots.ts
```

Verifique matematicamente:

### Geração

Exemplo:

```text
09:00–12:00
duration = 60
```

deve produzir:

```text
09:00–10:00
10:00–11:00
11:00–12:00
```

### Não ultrapassar janela

Nunca gerar:

```text
11:30–12:30
```

### Múltiplas janelas

Exemplo:

```text
09:00–12:00
14:00–18:00
```

deve produzir slots independentes.

### Sobreposição

Confirme:

```text
slot.start < occupied.end
AND
slot.end > occupied.start
```

### Appointments

Confirme que:

```text
CANCELLED
COMPLETED
NO_SHOW
```

não bloqueiam slots.

E que:

```text
CONFIRMED
IN_PROGRESS
```

bloqueiam.

### Blocked periods

Somente:

```text
ACTIVE
```

bloqueia.

### Resource

Para IN_PERSON:

* resource ACTIVE
* resource disponível
* pelo menos um resource compatível livre

### Professional service

Somente:

```text
professional_services.active = true
```

pode gerar slots.
