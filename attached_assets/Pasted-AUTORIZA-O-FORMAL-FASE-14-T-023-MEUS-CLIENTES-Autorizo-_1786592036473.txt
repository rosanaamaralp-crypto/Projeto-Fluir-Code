PROBLEMA AUTORIZADO:
O T-023 atualmente não possui endpoint que forneça ao PROFESSIONAL os clientes relacionados aos seus próprios atendimentos com dados humanos suficientes.

O workaround anterior foi removido/não deve ser recriado.

SOLUÇÃO PREFERENCIAL:
Criar um endpoint específico para os clientes relacionados ao profissional autenticado, preferencialmente no formato:

GET /api/me/professional/clients

O endpoint deve determinar o profissional exclusivamente pela sessão autenticada.

NÃO aceitar professionalId fornecido pelo frontend como mecanismo de autorização/ownership.

REGRA DE OWNERSHIP:
O profissional somente pode visualizar clientes que tenham relacionamento real com seus próprios atendimentos.

Nunca permitir que um PROFESSIONAL informe o ID de outro profissional para obter seus clientes.

O backend deve ser a autoridade final dessa regra.

DADOS MÍNIMOS DA LISTAGEM T-023:
- nome do cliente
- telefone
- identificador interno necessário para abrir o detalhe

A implementação deve considerar também os requisitos da TELA 25 / detalhe do cliente documentados oficialmente:
- nome
- data de nascimento
- telefone
- e-mail
- histórico de atendimentos permitidos
- endereço quando necessário para Home Care

ANTES DE CRIAR UM SEGUNDO ENDPOINT:
Verifique se é tecnicamente melhor que o endpoint T-023 já retorne os dados necessários para o detalhe, ou se um endpoint de detalhe específico é necessário.

Não duplicar APIs desnecessariamente.

SEGURANÇA:
- PROFESSIONAL: somente seus clientes relacionados aos seus atendimentos.
